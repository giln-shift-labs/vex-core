# Upgrading to 0.29

## From 0.28

A body is JSON only when its media type is `application/json`; parameters (`; charset=utf-8`) and case do not matter. Every place vex-core reads a body's type reads it with one helper, `mediaType`, and the two that require JSON refuse the rest with one, `requireJson`:

| Where | 0.28 | 0.29 |
|-------|------|------|
| `vexHandler`'s `/query`, `/mutate`, `/action` | any body parsed as JSON | any other type, or none: `415 { "error": "Content-Type must be application/json" }`, the call does not run |
| `readJson(req, limits)` | any body parsed as JSON | the same 415, thrown as an `HttpError` |
| `bodyParser` | `application/json*` (so `application/jsonp`) parsed as JSON | `application/json` only; urlencoded exactly; `text/*` as before |
| `bearerAuth` login | a type that *contains* `application/json` or the urlencoded type (so `text/plain; application/json`) | those media types exactly; anything else submits no token |

`/webhook/*` is unchanged.

Why: a browser sends a `text/plain`, urlencoded or multipart POST to another origin without a CORS preflight, carrying whatever cookies it holds for this one. A host that authenticates by cookie and reads such a body as JSON could be driven by any page that posts a form (SHFT-2831).

New in `vex-core/http`: `mediaType(headers)`, a body's media type alone, lowercased (`""` when absent), and `requireJson(req, limits)`, the 415 itself, for a route that reads its body some other way.

What breaks is a caller that sends JSON without saying so:

- `fetch(url, { method: "POST", body: JSON.stringify(data) })` with no `headers` sends `text/plain;charset=UTF-8`. Add `headers: { "content-type": "application/json" }`.
- `curl -d '{...}'` sends `application/x-www-form-urlencoded`. Add `-H 'Content-Type: application/json'`, or use `--json`.
- A route that calls `readJson` for a request with no body and no type, which read `{}`, now answers 415. Send the type, or do not read a body the route does not need.

`VexClient` calls over the WebSocket and is not affected.
