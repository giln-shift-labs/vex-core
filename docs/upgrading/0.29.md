# Upgrading to 0.29

## From 0.28

`vexHandler`'s `/query`, `/mutate` and `/action` take only a body sent as `Content-Type: application/json`. Parameters (`; charset=utf-8`) and case do not matter. Any other type, or none, is answered `415 { "error": "Content-Type must be application/json" }` before the body is read, and the call does not run. `/webhook/*` is unchanged.

| Request | 0.28 | 0.29 |
|---------|------|------|
| `Content-Type: application/json` (any parameters, any case) | runs | runs |
| `text/plain`, urlencoded, multipart, any other type | parsed as JSON, runs | 415 |
| no `Content-Type` | parsed as JSON, runs | 415 |

Why: a browser sends a `text/plain`, urlencoded or multipart POST to another origin without a CORS preflight, carrying whatever cookies it holds for this one. A host that authenticates calls by cookie could be driven by any page that posts a form (SHFT-2831).

What breaks is a caller that sends JSON without saying so:

- `fetch(url, { method: "POST", body: JSON.stringify(call) })` with no `headers` sends `text/plain;charset=UTF-8`. Add `headers: { "content-type": "application/json" }`.
- `curl -d '{...}'` sends `application/x-www-form-urlencoded`. Add `-H 'Content-Type: application/json'`, or use `--json`.

`VexClient` calls over the WebSocket and are not affected.
