# Upgrading to 0.28

0.28 extends 0.27's refusals ([Upgrading to 0.27](0.27.md)) to everything else the builder writes into SQL or reads its shape from, and to every path a read takes: an access-governed table's restricted reads, which apply them in JS, and subscriptions, which record what they read.

## From 0.27

| Position | Accepted | Anything else |
|----------|----------|---------------|
| any table, column or alias name | a non-empty string without NUL | `ArgsError` |
| `ctx.db.table(name)`, `vex.readTable(name)`, `vex.describeTable(name)` | not `sqlite_*` (SQLite's tables) or `__vex_*` (the storage's bookkeeping) | `ArgsError` |
| `whereAny(groups)`, `sqlOver` holds | arrays of filter objects; a hold is filters or `{ where, reads }` | `ArgsError` |
| `order(column, …)` | a name, or `null` for no order | `ArgsError` |
| `groupBy(columns, aggs)` | at least one column; aggregates an object of `"count"` or `[sum\|avg\|min\|max\|countDistinct, column]` | `ArgsError` |
| `insert(row)`, `update(id, data)`, `upsert(keys, data)` | objects; `upsert` names at least one key; `update`/`delete` ids non-empty strings | `ArgsError` |

Code that keeps to the builder's types needs no change. What breaks is an untyped value reaching it, as in 0.27.

- A table registered under a `__vex_*` name, which the storage reserved only for `__vex_sqlite_indexes`, now fails startup: rename it with `renamedFrom`.
- An empty or other non-name order column (`order("")`), which wrote no `ORDER BY`, is refused; `null` still means no order.
- An `upsert({}, data)`, which overwrote whichever row came first, is refused.
- A restricted read of a governed table compares a `groupBy`'s `having` value as SQL does (a boolean as 1 or 0, an object as its JSON text), so it answers as an unrestricted read does where it used to match nothing.
